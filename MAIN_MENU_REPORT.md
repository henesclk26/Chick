# Main Menu — UI Toolkit

## Current single-scene configuration — 2026-09-14

This section supersedes the historical scene/setup instructions below. Open **SampleScene** and press Play. It contains the menu UIDocument, settings, confirmation, gameplay gate and the in-game pause/settings layer. Build Settings contains only SampleScene. The separate MainMenu scene and its metadata, scene generator and runtime scene-handoff code were removed. Menu UXML/USS and PanelSettings are used by SampleScene. The menu background uses the supplied cover image at `Assets/UI/Menu/MainMenuCover.png` through UI Toolkit USS. The main card has no visible panel background, leaving only the cover, text and buttons. Text uses a restrained dark outline/shadow for contrast; buttons use opaque green and gold surfaces with clear pressed/hover states. The in-game pause layer also provides `KAYDET VE ÇIK`, which saves the current day/time, player transform, camera zoom/orbit angle and consumed edible IDs before reloading SampleScene to the embedded main menu.

Verified with isolated test saves: visible menu; disabled Continue without a save; New Game confirmation and cancellation; settings navigation; Continue restores day/time/position; New Game displays DAY 1 and starts gameplay in SampleScene. The broader legacy smoke test's combined zoom/sensitivity assertion failed; camera code was not changed in this pass. Removed scene files are not retained as a project backup.

## Deliverables (requested 14 points)

1. **UXML:** `Assets/UI/Menu/MainMenu.uxml`. Main page, settings page, new-game confirmation, display confirmation and loading overlay are authored in this single organized document.
2. **USS:** `Assets/UI/Menu/MainMenu.uss`. Warm cream/olive/gold palette, rounded buttons, hover/pressed/disabled/focus states, short entrance/interaction transitions and styled scrolling. CİVCİK is a replaceable placeholder title, not an assumed final game name.
3. **Runtime scripts:** `MainMenuController`, `SettingsMenuController`, `MenuPreferences`, `MenuAudioChannel`, `MenuChickIdle`, under `Assets/Scripts/Menu`. Editor-only setup/verification: `MainMenuSceneBuilder`, `MainMenuBuildVerification`. Opt-in tests: `MainMenuPlayVerification` and development-build-only `MainMenuBuildSmoke`.
4. **Scene:** `Assets/Scenes/SampleScene.unity` is the only scene and the first enabled Build Settings scene. The menu UIDocument, `MainMenuGameplayGate` and `InGamePauseMenuController` all run in this same scene. The gate holds the existing gameplay start until a menu choice, then releases the unchanged DAY flow in place. There is no separate MainMenu scene or scene handoff.
5. **UIDocument:** `Main Menu — UI Toolkit` owns one UIDocument using `MainMenu.uxml` and the separate `Assets/UI/Menu/MainMenuPanelSettings.asset`. Reference resolution 1280×720, scaled to the display. Its references and controllers are assigned in the saved scene.
6. **No Canvas:** confirmed by runtime hierarchy enumeration and source inspection in both menu paths. `SampleScene` contains its existing UI Toolkit HUD/transition plus the new UI Toolkit menu document; Canvas count is zero.
7. **No TextMeshProUGUI:** none used or added.
8. **Visible UI:** entirely UI Toolkit: VisualElement, Label, Button, Slider, Toggle, DropdownField and ScrollView. All visible hierarchy is UXML-authored, not generated by controller code. The farm behind the menu is ordinary 3D scene geometry, not legacy UI.
9. **Continue validation:** calls `FarmSaveSystem.Load()`, including its validation and backup fallback. Null/invalid saves disable (do not hide) DEVAM ET. Validity is checked again on click. `GameTimeManager.Start()` restores day/time/player/zoom, camera yaw/pitch and consumed edible state before the morning transition opens; simply opening a blank gameplay scene is not treated as Continue. Saves created before these extra fields remain valid and use the original default camera orbit with all edibles present.
10. **New Game:** any existing primary/backup file, including unreadable files, requires the UI Toolkit confirmation. HAYIR closes it without touching storage; EVET atomically writes a fresh `FarmSaveData` through the existing `SaveAsync`. The existing save system keeps its normal recovery backup; no new competing progress storage was created. Busy/loading state prevents repeated submits. Write/load failures keep the user in the menu with a message.
11. **Settings:** master/music/SFX sliders, fullscreen toggle, resolution dropdown, VSync toggle, project quality presets and 0.5–2× mouse sensitivity. UYGULA persists preferences in a namespaced PlayerPrefs group; GERİ discards un-applied changes and returns to home. The same settings page is reused from the in-game pause screen. Master controls AudioListener; `MenuAudioChannel` routes music/SFX independently. There are currently no audio clips or gameplay AudioSources in the supplied project, so no soundtrack was invented; both routes were verified with temporary sources and are ready for future audio. Runtime display changes have a 15-second keep/revert safety dialog. Editor resolution/fullscreen changes are saved for the player without resizing the editor window. Quality/VSync/audio apply directly, and camera sensitivity is applied immediately to the active camera.
12. **Quit:** production uses `Application.Quit()`. Editor uses `EditorApplication.isPlaying = false`; the actual UI Toolkit button successfully stopped Play Mode without errors.
13. **DAY 1:** fresh data contains day 1, 07:00, original scene spawn `(0,0,0)`, identity facing, approved fresh zoom `.83` and no consumed edibles. In the embedded `SampleScene`, the gate releases the unchanged black hold → DAY 1 → morning fade → controls-enabled sequence in place. Day progression and time-of-day visuals were not modified.
14. **Inspector:** no manual assignments required. Open MainMenu and press Play, or build normally. Title can be replaced in the named `brand` / `game-title` UXML area. Future music/SFX AudioSources should receive `MenuAudioChannel` with the matching bus.

## Scope confirmation

PlayerController, eating input/targeting, jump, animations, Animator and time-of-day behavior remain unchanged. Camera save support exposes and restores its current yaw/pitch, then uses the one-frame `SnapToTarget()` load placement; sensitivity values and normal orbit/zoom/collision/smoothing behavior were not retuned. Edible objects now expose stable scene-hierarchy IDs solely for persistence.

The menu stores **preferences only** in PlayerPrefs; **game progress remains exclusively FarmSaveSystem**. During gameplay, Esc opens the pause overlay, freezes time/player/camera, and exposes Resume, Settings and Save and Exit; Save and Exit atomically stores the current position, clock, zoom, visible camera orbit and consumed edible IDs, restores normal time/cursor state and reloads the same SampleScene to show the menu. Esc from settings returns to the pause overlay.
